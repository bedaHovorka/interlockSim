# SP12.2 — Release and rollback: seams for Goal 9B

**Issue:** bedaHovorka/interlockSim#1168 (Goal 1B, SP12 leaf 2 of #1159) · **Date:** 2026-10-11

SP12.2 moved route release and rollback out of `DefaultPathReservationService` into the internal
class `RouteReleaser` (same package, `context/navigation/`). It is a pure extraction: no
behaviour changed, every `PathReservationService` / `BlockRollbackStep` entry point stays on the
service and delegates, and `RegistryPartialRouteReleaser` and `InterlockingFacade.releaseRoute`
still call through the existing interface.

This file records, for the release side of routing, which seams a Goal 9B dispatcher may call
and which must stay private (the SP12 deliverable `SP12-routing-decomposition.md` inherits it).

## What moved

| Moved into `RouteReleaser` | Role |
| --- | --- |
| `releasePath`, `releasePathDetailed`, `release`, `keptBlocks`, `approachLockedBlocks`, `isOccupied`, `boundarySemaphores`, `releaseAllBlocks`, `releaseAllBut`, `cancelBlock` | whole-route release, with and without approach locking (Issue #1050) |
| `unregister` | train-completion release |
| `unregisterBlock`, `dropFreedBlock`, `releaseBlock`, `ownsBlock` | the per-block release funnel (Issue #961) |
| `rollbackBlock`, `rollbackReservation`, `rollbackBlocks`, `logRollbackOfBlock` | rollback of a reservation that was never announced |
| `emitBlockReleased` | the one release-event emitter (kDisco bus + legacy listener) |
| `approachLockDeferredUntil`, `APPROACH_LOCK_DEFER_SECONDS` | the approach-lock deferral window, owned only by release |

The unit depends on the `PathReservationRegistry` and on three callbacks into the service: the
signal ledger (`resetSemaphoresForReleasedBlocks`, `resetClearedSemaphores`) and the
blocked-contention tracking (`clearBlockedTracking`). The signal ledger stays with the service;
the contention tracking already moved into `ReservationContentionTracker` (SP12.1, #1167), so that
callback points at the tracker. The remaining extraction (signal configuration) is a sibling SP12
leaf and only changes what the signal callbacks point at.

**Not moved:** `rollbackRouteLocks` lives in `DefaultInterlockingFacade` (`sim/`), not in the
service. SP12 keeps the facade as it is, and the function uses the facade-private
`RouteLockOutcome`, so it stays where it is, untouched and with its known corner (it drops a
switch an earlier route of the same train flank-locked) intact for #1173. The switch cleanup
before a candidate (`releaseOrphanSwitchLocks`, `reclaimStaleForeignSwitchOwnership`,
`releaseCandidateSwitches`) stays in the service for the switch-configuration leaf (#1170);
`rollbackUnconfigurableCandidate` stays with the reservation code that calls it and reaches the
moved `rollbackBlock` through the service. `RouteReleaser` owns block release and rollback only.

## Seams a Goal 9B dispatcher may call

Only through the ports a dispatcher already has; none of these is a new entry.

| Seam | Caller today | Why it is safe for a dispatcher |
| --- | --- | --- |
| `PathReservationService.releasePathDetailed` | `DefaultNetworkActuatorPort.releaseRoute` (`cancel_route`, orphan sweeper), `DefaultInterlockingFacade.releaseRoute` | Signals to STOP first, approach locking keeps a block a train may be booking, the caller retries on `PathRelease.deferred`. This is the release a dispatcher means by "cancel this route". |
| `PathReservationService.releaseBlock` (after `resetSemaphoresForReleasedBlocks`) | `RegistryPartialRouteReleaser` | Committed release of one owned block, refusing a block another train owns. The caller must reset the signals first, or a far route START stays lit (pinned by `PathReservationReleaseAndRollbackBlockTest`). |
| `PathReservationService.dropFreedBlock` | `RegistryPartialRouteReleaser` | Drops a block that is already FREE; refuses anything still RESERVED or occupied. |

A Goal 9B dispatcher should keep calling these through `NetworkActuatorPort` /
`RegistryPartialRouteReleaser`, not hold a `PathReservationService` of its own:
`TargetSelectionSingleEntryTest` allow-lists the classes that may store the service.

## Seams that must stay private to the simulation

| Seam | Owner | Why a dispatcher must not call it |
| --- | --- | --- |
| `releasePath` | teardown and tests | Unconditional: no approach lock, so it can free a block a train is booking across a proceed aspect (the Issue #1050 FATAL). |
| `unregister` | `DefaultSimulationContext` on journey completion | Wholesale end-of-journey cleanup; calling it for a running train strands the train on unregistered track. |
| `unregisterBlock` | `Train.Tail` via `SimulationEnvironment.unregisterBlock` | Follows physical progress (the tail leaving a block); a dispatcher does not know when that happened. |
| `rollbackBlock` (`BlockRollbackStep`) | reservation code, `DefaultInterlockingFacade` rollback | Undoes a reservation that was never announced, so it publishes no release event; using it for a granted route would hide the release from every listener. |
| `rollbackReservation`, `emitBlockReleased`, approach-lock internals | `RouteReleaser` (internal class) | Steps inside one reservation or release; no meaning outside it. |
