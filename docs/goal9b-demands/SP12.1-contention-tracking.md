# SP12.1 — Contention and blocked tracking: demands on Goal 9B

**Issue:** bedaHovorka/interlockSim#1167 (Goal 1B, SP12.1, under SP12 #1159) · **Date:** 2026-10-11

SP12.1 moved the contention and blocked-request tracking out of `DefaultPathReservationService`
into its own unit, `ReservationContentionTracker` (`internal`, same package
`context/navigation/`). Pure move: no behaviour change, no public API change of
`PathReservationService`. The service keeps one field (`contention`) and delegates.

## What moved

| Moved into `ReservationContentionTracker` | Role |
| --- | --- |
| `blockedSince` map + the Issue #612 disambiguation rationale | which (train, block) contentions are open |
| `recordContentionAndEmitIfNew` | records a contention; emits `ConflictDetectedEvent` once per contention |
| `recordBlockedContention` (private) | first-observation dedup |
| `flushUnresolvedConflicts` body | end-of-run `BlockEvent.ReservationConflictDetected` list |
| `clearBlockedTracking` | forgets a train's contention on Success / whole-route release |
| `findFirstBlockedConflict` | first busy block of another train, with its owner |
| `ownerOf` (private) | registry owner, block `trainName` as fallback |

Left in the service on purpose: `classifyExhaustedAttempt` (it classifies the reservation outcome —
geometric / divergent / blocked — and only *calls* the tracker on the blocked branch) and the
`recordAttemptResult` / `recordBlocked` helpers of `reservePathToAnyNextSemaphore` (result-priority
aggregation across candidate semaphores, not contention state).

The tracker takes the `PathReservationRegistry` (owner lookup) and an emitter seam
(`(ConflictDetectedEvent) -> Unit`, kDisco `emitCustom` by default), so it is unit-testable outside a
running simulation.

## Seams: call directly vs keep internal

| Seam | Goal 9B dispatcher | Why |
| --- | --- | --- |
| `ConflictDetectedEvent` (kDisco custom event, mid-run) | **Consume** (subscribe) | It is the existing, already-public mid-run signal "train X is blocked by train Y on block B". Emission semantics differ per producer: the AllPathsBlocked arm (`recordContentionAndEmitIfNew`) emits ONCE per contention; the atomic-registry-race arm (`rollbackRegistryConflict`) is NOT deduplicated and emits one event per detected race. Never pauses the run; a dispatcher that must tolerate re-emission de-duplicates by (train, block) itself. |
| `PathReservationService.flushUnresolvedConflicts` | **Do not call** | End-of-run only. `DefaultSimulationContext.run` calls it exactly once after the event loop stops; it *clears* the tracking, and a mid-run call reintroduces the Issue #612 false-positive auto-pause. The prohibition is convention-only for now -- the method is still public on the facade; D1's read-only snapshot is where it stops being usable by dispatchers. |
| `ReservationContentionTracker.findFirstBlockedConflict` | **Internal (not exposed to a dispatcher); candidate for a read-only query through the service** | Pure query, no state. It answers SP5's demand D5 ("blocked by <train>") for one candidate route, but it must be reached through `PathReservationService` / the facade so the single-entry discipline (SP5, `TargetSelectionSingleEntryTest`) holds. |
| `recordContentionAndEmitIfNew` | **Internal (not exposed to a dispatcher)** | Mutates the dedup state; its correctness depends on being called only from `reservePath`'s `AllPathsBlocked` branch. A dispatcher calling it would emit spurious conflicts or suppress real ones. |
| `clearBlockedTracking` | **Internal (not exposed to a dispatcher)** | Must stay coupled to a real reservation Success or whole-route release; a dispatcher clearing it would hide an unresolved deadlock from the end-of-run flush. |
| `blockedSince` / open-contention set | **Private; read-only snapshot is a demand** | See D1. |

## Demands

### D1 — A read-only view of open contentions

Today a dispatcher learns about a contention only through the one-shot `ConflictDetectedEvent`;
whether it is *still* open is invisible until the run ends. A dispatcher that wants to rank trains
by how long they have waited must keep its own shadow copy of the event stream and guess when a
contention resolved (the tracker forgets it silently on Success).

**Goal 9B demand:** a read-only snapshot through `PathReservationService` — open (train, block,
owner, since) tuples — never the mutable tracker itself. The `since` time is already recorded in
`blockedSince` and is currently written but never read.

### D2 — A "resolved" signal

There is an event for *contention began* but none for *contention resolved*. Pairing them would
let a dispatcher measure waiting directly.

**Goal 9B demand:** either a resolution event or the snapshot of D1; one of the two, not both.

### Observed quirk (pinned, not changed)

`releasePath` forgets a train's contention only on its whole-route branch, so a blocked train that
holds no block and releases keeps its contention until the run ends
(`PathReservationContentionTrackingTest`, "releasing a blocked train that holds no block keeps its
contention"). SP12.1 is a pure move and pins this as-is; whether it should change is a
behaviour question for a `[sim]` leaf, not for this extraction.
