# SP12.5 — Target discovery: seams for Goal 9B

**Issue:** bedaHovorka/interlockSim#1171 (Goal 1B, SP12.5; parent SP12 #1159) · **Date:** 2026-10-11

SP12.5 moved reservation **target discovery** — *which separators a route can be set to, and in
which order they are tried* — out of `DefaultPathReservationService` into a new read-only class,
`ReservationTargetDiscovery` (same package, `internal`). It is a pure extraction on top of SP5's
single target-selection path: no behaviour change, no public API change.

## What moved

| Moved into `ReservationTargetDiscovery` | Was in the service as |
| --- | --- |
| `resolveForwardSection` | private helper (Issue #957) |
| `findNextSemaphoresVia` + its BFS helpers `processReachedSeparator`, `exploreOutgoingPaths`, `prioritizeInOuts`, `calculateTravelDirection` | private helpers |
| `findReservationTargetCandidates` (candidate building, Issue #970) | body of the `ReservationTargetQuery` override |
| `isAnyNextTargetAvailable` | body of the `isPathToAnyNextSemaphoreAvailable` override |
| `isPathAvailableFor` (switch-constrained, owner-aware availability, Issue #1060) | private helper |
| `reservePathToAnyTargets` (steps 1–3: collect InOuts and semaphores, sort InOuts by orientation and path length, InOuts first) | inline in `reservePathToAny` |
| `allSemaphores` cache (Issue #965) | private lazy property |

What stayed on the service: every `override fun` entry point (now a one-line delegation), and both
attempt loops that call `reservePath` — `reservePathToAny` step 4 and the bypass-checking loop of
`reservePathToAnyNextSemaphore`. Discovery says *what to try*; the service still decides *what
happened* and owns every mutation. `TargetWithPaths` (target + lazy topological paths, Issue #966)
is the hand-over type, so the paths enumerated for sorting are still reused by the attempt.

Two incidental, behaviour-neutral cleanups came with the move: the two `@Suppress("UNCHECKED_CAST")`
on the graph's edge map are gone (`SimulationEnvironment.getGraph()` already types the edges as
`DynamicTrackBlock` by `Cell.Segment`), and `DEFAULT_MAX_PATH_DEPTH` became `internal` so both classes
share one bound. `@Suppress("LargeClass")` stays on the service (SP12's last leaf removes it).

## Seams: what a Goal 9B dispatcher may call, and what stays private

**Call directly (already public, unchanged by this move):**

- `ReservationTargetQuery.findReservationTargetCandidates(start, ownerTrainId)` — *the* dispatcher
  seam. Every settable next separator one section ahead, each with an evaluated availability. A
  dispatcher chooses from this list through `ReservationTargetPolicy.pick` (SP5); the
  `TargetSelectionSingleEntryTest` allow-list keeps it that way.
- `PathReservationService.isPathToAnyNextSemaphoreAvailable` — the shell's (`InOutWorker`) "may a
  train enter at all" probe. A dispatcher does not need it: the candidate list answers the same
  question per target.

**Keep private (`internal` in `ReservationTargetDiscovery`):**

| Function | Why a dispatcher must not call it |
| --- | --- |
| `findNextSemaphoresVia` | The raw enumeration without availability. Selecting from it is a second opinion about which route to set — exactly what SP5 removed. It also throws on a start with no grid location or no connection to `next`. |
| `reservePathToAnyTargets` | The interlocking's own fallback order for `reservePathToAny` (exits first, opposite side first). It is a policy of the *interlocking*, not a dispatcher input, and its lazy path lists are only valid inside one `reservePathToAny` call. `reservePathToAny` has no production caller outside the navigation package today. |
| `isPathAvailableFor` | The availability verdict. It reaches a dispatcher only as `CandidateTarget.available`; calling it directly would let a dispatcher probe arbitrary pairs, beyond the one-section horizon the interlocking commits to. |
| `resolveForwardSection` | Geometry plumbing (orientation → forward section). Meaningless without the enumeration around it. |
| `allSemaphores` | A grid-scan cache; the observation port already gives a dispatcher the signals it may see. |

## Where the SP5 demands would land

The extraction puts the SP5 demands on Goal 9B (D1–D5 in `SP5-target-selection-path.md`) next to
the code that would carry them. No demand is addressed here.

- **D1 priority / cost:** `reservePathToAnyTargets` already computes a shortest path length per
  InOut to sort them; the one-section-ahead enumeration computes none. A per-candidate cost would be
  computed in `findReservationTargetCandidates`, not in the service.
- **D3 unavailability reason:** `isPathAvailableFor` collapses "occupied", "reserved by another
  train" and "no switch-legal path" into one `false`. A structured reason would replace its return
  type; the service is not involved.
- **D4 horizon:** `findNextSemaphoresVia` stops at the first layer of forward-facing semaphores by
  design (BFS `stopExploration`). A multi-hop view is a new enumeration beside it, not a change to it.

## Review round 2 (2026-10-25)

Template code review + simulation-domain review + a 4-angle `/simplify` round on the shipped
stack: extraction confirmed pure, verdict "with fixes". Fixes shipped (none change behaviour):

- The pin commit had carried a from-switch order pin recorded on the unguarded base — on this
  guarded base it cannot be run; the pin commit now holds the refusal pin only, and the
  from-switch order for vA and vB is pinned directly on the extracted class.
- The test-only `allSemaphores()` pass-through is gone; `ReservePathToAnyDedupTest` reaches the
  cache on the owning class. One duplicate cache pin dropped (one oracle stays).
- The private `label()` helper was re-implementing the shared `separatorLabel`; replaced. The
  `separator(name)` helper builds one name map per test instead of re-scanning the grid.
- The single-caller `isPathAvailableFor` wrapper on the service is inlined; the Issue #797
  rationale stays once, on the implementation.
- `DEFAULT_MAX_PATH_DEPTH` moved next to the interface `maxDepth` defaults, which now reference
  it — the enumeration bound and the interface defaults can no longer drift.
- `ForwardSectionResolutionTest`'s KDoc retargeted at the extracted class.

New pins (all pin existing behaviour): the from-switch order (vA, vB), owned-blocks-free for the
owner vs. another train (Issue #1060) and the unconnected-next throw — each of the three proven
by a targeted mutation that fails exactly that pin; the direction-agnostic behind-block probe
(no mutation isolates it without touching neighbouring pins — noted here); the static-InOut
unwrap contract; the InOut-behind enumeration; the TRACE-level verdict sweep. After the round:
16 uncovered lines in `ReservationTargetDiscovery.kt`, each unreachable under this domain's
invariants — the same documented pattern as the SP12.2 round:

- static halves of the `is InOut` arms — the tracked grid enumerates dynamic wrappers only;
- the location guards (`?: return` / `?: throw`) — XML validation guarantees cell locations;
- the unreachable-InOut sort arm (`?: Int.MAX_VALUE`) — every InOut is topological on
  `vyhybna.xml`;
- the empty-BFS branches — no core fixture has an oriented separator whose walk finds nothing;
- the file-scope `logger` init's partial half-line.

The unreachability is the domain invariant itself (XML-validated inputs, dynamic-wrappers grid),
not a coverage gap. Follow-ups filed under #1159: narrow `reservePathToAnyTargets` to
[OrientedPathSeparator], unify the two parallel next-target loops, tighten the `TargetWithPaths`
hand-over type.

## Follow-ups #1207-#1209 (2026-10-25)

The three follow-ups filed after review round 2. Unlike the extraction they are small refactors,
but none changes routing behaviour or log text.

- **#1207 — oriented-only target discovery.** `reservePathToAnyTargets` now takes an
  `OrientedPathSeparator`. The orientation-free `else` sort arm (InOuts by distance only) is gone:
  `reservePathToAny` refuses a non-oriented origin (Issue #1188 guard) before discovery, so a
  switch start never reached it. The from-switch order pins (vA, vB) recorded pre-guard lineage
  and are converted to an InOut-start pin (A, B); the refusal pin
  (`switchStartIsRefusedBeforeDiscovery`) stays. The arm was pinned and therefore never appeared
  in the uncovered-lines list above, so that list is unchanged.
- **#1208 — one next-target primitive.** `findReservationTargetCandidates` and
  `isAnyNextTargetAvailable` were the same `findNextSemaphoresVia` plus per-target
  `isPathAvailableFor` composition at two entry levels. Both now enumerate once with
  `findNextSemaphoresVia`, log what they found, and evaluate on
  `evaluateTargets(start, targets, ownerTrainId)`, which returns a lazy `Sequence` of candidates
  (target plus availability) and does not log. The candidate query materialises it (every
  candidate stays evaluated, Issue #970); the boolean probe short-circuits on the first available
  candidate and still passes `ownerTrainId = null`. The early stop is pinned by counting
  `findAllSwitchConstrainedPaths` calls (`ReservationTargetDiscoveryTest.NextTargetPrimitive`):
  one evaluation for the probe, two for the candidate query, on the same two targets. Every log
  line of both callers is unchanged.
