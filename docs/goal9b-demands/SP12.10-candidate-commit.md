# SP12.10 — Candidate commit, finalize and rollback: seams for Goal 9B

> SP12 status index: [SP12-routing-decomposition.md](SP12-routing-decomposition.md) collects the Goal 9B seam list, the duplicate-check report and the size numbers for all SP12 leaves (SP12 closed on 2026-10-29, #1159). This page keeps the leaf evidence.

**Issue:** bedaHovorka/interlockSim#1211 (Goal 1B, SP12.10; parent SP12 #1159) · **Date:** 2026-10-25

SP12.10 moved the **candidate commit, finalize and rollback** steps — everything that mutates state
for one screened candidate path and undoes exactly that candidate when a step fails — out of
`DefaultPathReservationService` into a new class, `CandidateCommitter` (same package, `internal`).
It is a pure extraction: no behaviour change, no public API change, no log or denial text change,
and every side effect and every rollback snapshot keeps its order. The moved log lines' message
text is byte-identical; their `%logger` name now reports `CandidateCommitter` (message-only
identity, as in every SP12 extraction). The service no longer needs
`@Suppress("LargeClass")` (the #1159 acceptance criterion) or `@Suppress("LongMethod")` on
`reservePath`; both are gone and `:core:detekt` is green without them.

On PR #1216 review the owner asked to split two flagged long bodies, and every step group inside
them was second-level extracted (still private): Step 2e's PathInfo build (`buildCandidatePathInfo`),
Step 2e.5's ownership reclaim (`reclaimCandidateSwitchOwnership`), Step 2g's START signal and its
failed branch (`configureCandidateStartSignal`, which owns its rollback like every step helper),
and Step 2c's catch path (`rollbackAndClassifyReservationFailure`). The table's rows still name
the step owners.

`CandidateRequest` is now a top-level `internal` class because the service builds it;
`CandidatePreparation` is file-private. The service's one-line `rollbackReservation` forwarder is
gone: the committer calls `RouteReleaser.rollbackReservation` and `RouteReleaser.rollbackBlock`
directly. The committer takes the service's own collaborators — `registry`, `pathInfoBuilder`,
`switchConfigurator`, `signalConfigurator`, `signalLedger`, `contention`, `releaser` and the
`RouteCandidateScreen` (for `forwardOnlyPathInfo`) — and no `environment`: nothing moved reads it.

What stayed on the service: the orchestration (`reservePath` calls the screens, then
`tryAtomicReservation`, then `registerAndFinalizeCandidate`, in the same order), the already-owned
early return, `classifyExhaustedAttempt`, and the target-attempt loops
(`reservePathToAnyNextSemaphore`, `reservePathToAny`) with their bypass rollback. The loops are not
extracted: they call back into `reservePath`, so a cut there needs a `reservePath` callback and is
a separate decision.

## The rollback contract

Every rollback is scoped to the candidate being attempted. The snapshots that make this possible
are taken in `prepareReservedCandidate`, before the first mutation they guard, and are carried in
`CandidatePreparation`:

- `priorSwitches` — the switches the train already owned. Only candidate switches *not* in this set
  are unlocked and unregistered, so an earlier hop's switches survive.
- `clearedBeforeCandidate` — the semaphores already cleared for the train. A failed START signal or
  a merge abort resets only what this candidate cleared, so an earlier hop's lit signal survives.

`rollbackUnconfigurableCandidate` releases only the candidate's `forwardBlocks`, each through
`RouteReleaser.rollbackBlock`, and publishes no release event: every caller runs before
`reservePath` announces the blocks (Issue #961). The registry-conflict arm rolls back
`forwardBlocks`, never the train's already-held blocks (Issue #1025).

## Seams: what a Goal 9B dispatcher may call, and what stays private

**Call directly:** nothing new. The commit steps are not a dispatcher input; their outcomes reach a
dispatcher as the existing `ReservationResult` values (`Success`, `Conflict`, `AllPathsBlocked`,
`GeometricallyImpossible`), whose reason strings were not touched.

**Keep private (`internal` in `CandidateCommitter`):**

| Function | Why a dispatcher must not call it |
| --- | --- |
| `tryAtomicReservation`, `registerAndFinalizeCandidate` | Steps of one `reservePath` transaction. Calling them alone reserves blocks without the screens, the ledger snapshots or the target classification. |
| `rollbackUnconfigurableCandidate` | Only correct with the `priorSwitches` snapshot taken for the same candidate; with any other set it releases a live route's switches. It is reachable from tests through `service.candidateCommitter`, not through `PathReservationService`. |

## Where the Goal 9B demands would land

No demand is addressed here. The extraction only puts the transactional commit in one place:

- **A new commit-time precondition** (for example a dispatcher-supplied hold that must be re-checked
  just before registration) is a new step in `registerAndFinalizeCandidate`, with its rollback
  beside the existing ones, not a change in the service.
- **Structured outcomes** (a machine-readable rejection instead of the `null` of a rejected
  candidate) would change the return type of `registerAndFinalizeCandidate` and the
  `GeometricFailures` it threads through.

## Acceptance evidence

- **Pure move:** existing tests unmodified except the two direct callers of
  `rollbackUnconfigurableCandidate` (`PathReservationReleaseAndRollbackBlockTest`,
  `PathReservationRollbackCleanupOnCancelThrowTest`), which now call it through
  `service.candidateCommitter`; only the call changed, not the assertions. Filtered runs of
  `cz.vutbr.fit.interlockSim.context.navigation.*` (plus `TargetSelectionSingleEntryTest`) under
  `jvmTest` and `integrationTest`, and of `cz.vutbr.fit.interlockSim.sim.*`, were green.
- **`CandidateCommitterTest`** (core jvmTest, 13 tests) pins the moved functions on the service's own
  wiring: `tryAtomicReservation` (success, a taken later block, an unexpected exception),
  `registerAndFinalizeCandidate` (commit, `BlockReserved` scope on an extension), and each rollback
  against the real registry — registry conflict (held route intact), failed START signal
  (partial-write fault, and the G4 rear-facing START), merge abort (fresh candidate, and an
  extension that must keep the earlier hop's blocks, switches, PathInfo and lit START) and
  `rollbackUnconfigurableCandidate` (switch filtering, block scope, no release event). Three
  mutations (conflict rollback over all blocks, no `priorSwitches` filter, merge abort without the
  signal reset) each fail at least one of them.
- **Size** (class-body code lines — blank and comment lines excluded; at the leaf's merge; current sizes in [the parent, section 4](SP12-routing-decomposition.md#4-size-outcome)):
  `DefaultPathReservationService` 916 (e3fade0f) → 752 (SP12.9) → 441 (this PR). `CandidateCommitter` 345.
  File length 1,621 → 979 lines for the service; `CandidateCommitter.kt` 720 lines.
  Review-round size (own simpler counter — empty, `//` and `/*…*/` lines excluded; comparable to
  itself only, not to the anchors above): `CandidateCommitter` 329 → 314 class-body code lines and
  723 → 744 file lines across the review round; `DefaultPathReservationService` unchanged at 443
  code lines (only its comments re-point moved helpers).
- **Quality gates:** `:core:compileKotlinJvm`, `:core:compileKotlinLinuxX64`, `:core:detekt`,
  `:core:ktlintCheck` green; no new `@Suppress`, and the two removed.
- **Standing constraint** (SP12 is closed; it applies to every later change in this area):
  `reservePathToAnyNextSemaphore`'s `next` overload sits at about 99 of the 100 `LongMethod` lines; add no
  line to it, and re-run `:core:detekt` on every later change to `reservePath`.
